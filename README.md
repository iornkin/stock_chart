# US Stock Insight: 미국 주식·ETF 분석 웹사이트

PC와 모바일 브라우저에서 사용하는 미국 주식·미국 상장 ETF 분석 사이트입니다.
다음 정보를 한곳에서 확인할 수 있습니다.

- 주가 차트와 거래량
- 기술적 지표
- 기업 재무 정보와 ETF 운용 정보
- 배당·분배금 기록
- 관련 뉴스·SEC 공시
- 종목별 일일 투자 브리핑
- 내 자산 관리(간편 입력·거래 내역): 종목별 수익률·총수익률, 달러 기준 ↔ 원화 기준(환율 반영) 전환, 해외주식 양도소득세 추정
- 목표 배당 계산기("매달 ○○만 원 받으려면 얼마?")
- 과거 백테스팅(양도소득세 반영 선택), 벤치마크 비교, 위험 지표(소르티노·칼마·VaR·CVaR·베타·알파·추적오차·정보비율·이동 창), 미래 시뮬레이션(시나리오·몬테카를로·가정 민감도), 스트레스 테스트, 전략 저장·비교
- 기술적 지표 27종(차트에 추가·제거·파라미터·저장)과 지표 전략 검증(다음 봉 체결·비용·학습/평가·파라미터 민감도·워크포워드·시장 국면·미래 정보 검사)
- 휴대폰·PC 홈 화면에 앱처럼 설치(PWA)

회원가입·계좌 연결이 없습니다. 개인 데이터는 브라우저(IndexedDB)에만 저장되고, 계산은 브라우저 안에서 합니다.

## 1. 주요 기능

### 차별화 기능 (매일 확인하는 분석)

| 기능 | 무엇을 보여 주나 | 근거 데이터 |
|---|---|---|
| **종목별 일일 변화 분석** | 직전 거래일과 오늘의 상태를 같은 규칙으로 계산해 **새로 생긴 변화만** 보여 줍니다(이동평균 돌파·이탈, RSI 구간 진입, MACD 교차, 52주 신고가·신저가, 평소보다 큰 등락·거래량, 고점 대비 −10/−20% 진입, 배당락·새 배당 발표, 실적 D-7). 변화가 없으면 "특별한 변화 없음"으로만 표시합니다. 전일 대비 수치 비교표를 함께 둡니다. | 일봉·뉴스·일정·배당 기록 (`src/lib/briefing/signals.ts`) |
| **종합 판단** | 추세·모멘텀·상대강도를 −1/0/+1 로 매겨 "상승 우위 / 중립 / 하락 우위"로 분류하고, 주의할 점(과열·실적 임박·레버리지·옵션 전략)과 확인할 가격·일정을 보여 줍니다. 판단마다 근거 자료를 연결하며, 투자 권유가 아닌 규칙 기반 해석임을 표시합니다. | `src/lib/briefing/judgment.ts` |
| **배당·분배금 분석** | 지급 완료·지급 예정·발표됨 구분, 연도별 합계와 증감·연평균 증가율, 최근 24개월 월별 지급 패턴, 보유 수량 계산기(실제 지급 기준·발표분·'가정' 구분), 재투자 vs 현금 수령 성과, 수익률 변화 분해(가격 효과 vs 분배금 효과). 여러 종목의 월별 현금흐름은 `/income`. | 배당 기록·일봉 |
| **레버리지 ETF 분석** (`/leverage`) | QQQ·QLD·TQQQ, S&P 500 계열, SOXX·SOXL 을 공통 기간으로 비교: 기간별 수익률과 '배수 대비' 차이, 변동성, 최대 낙폭, 급락 구간 손실과 회복 기간, 1년 보유 결과 분포, 연도별 성과. 하루 목표와 장기 성과의 차이를 계산 예시로 설명합니다. | 상장 이후 일봉·분배금 (`src/lib/leverage.ts`) |
| **ETF 관계 지도** (`/map`) | 설정 파일의 기초지수·전략으로 묶은 관계 그림. 종목을 누르면 같은 묶음의 1년 수익 차이·변동성·상관계수·상위 편입 종목 중복을 비교하고, M7 종목을 담은 ETF 와 비중을 보여 줍니다. | 설정 파일·상위 편입 종목·일봉 (`src/lib/etf-map.ts`) |
| **투자자 대시보드** (`/`) | 맨 위 "오늘 확인할 것"(시장 변화, 큰 변화 종목, 배당락 임박, 실적·경제 일정, 레버리지 위험 한 줄, 수집 실패), 내 투자 요약, 관심 종목의 새 변화, 시장 움직임(새 변화·상승·하락·거래량 탭), 데이터별 마지막 갱신 시각. | 위 기능 결과 |

### 개인 투자 도구 (브라우저에서 계산·저장)

| 메뉴 | 내용 |
|---|---|
| **내 자산** (`/portfolio`) | **간편 입력**(티커·수량·평균 단가·최초 매수일·평균 환율·메모·현금) 또는 **거래 내역**(매수·매도·입금·출금·분배금 수령·분배금 재투자·기초 보유, 수수료·세금·거래 당시 환율). 간편 입력 → 거래 내역 전환은 보유분을 '기초 보유', 현금을 '입금'으로 한 번만 옮겨 중복 계산이 없습니다. 총자산·평가금액·현금·매수 원가·미실현/실현 손익·총수익률(순납입 원금 대비)·종목별/ETF 유형별 비중·실제 누적/최근 12개월 분배금·예상 연간 분배금(추정 표시)·이번 달 지급 일정·자산 가치 변화 차트·**수익률**: 위쪽 버튼으로 **달러 기준 ↔ 원화 기준(환율 반영)** 전환 — 총자산·총수익률·평가 수익률·종목별 총손익(평가손익+실현손익+받은 분배금)과, 원화 기준에서는 환율 효과(환차익·환차손)를 보여 주고 두 기준의 총수익률을 한 줄로 비교합니다. 입력 목록에도 종목별 수익률이 바로 표시됩니다. 보유 기간에 실제 지급된 분배금 중 기록하지 않은 것을 찾아 제안합니다. **세금 탭**: 연도별 해외주식 양도소득세 추정(선입선출법·이동평균법 선택, 매도마다 원화 환산 손익), 올해 남은 기본공제, '지금 전부 판다면' 추가 세금, 금융소득 종합과세 기준(연 2,000만 원) 대비 분배금. |
| **내 자산 → 성과 분석** | 거래 내역 모드에서 **시간가중수익률(TWR)** 과 **금액가중수익률(XIRR)** 을 따로 보여 줍니다. 순납입 원금(입금 − 출금 + 기초 보유), 기준일 종가 평가금액, 실현·미실현 손익, 누적 분배금(세전·원천징수), **재투자한 분배금과 현금으로 받은 분배금을 나눠** 집계, 투자 기간, 1년 이상이면 연환산. "총손익 = 미실현 + 실현 + 세후 분배금" 검증 줄로 입출금이 수익에 섞이지 않았는지 보여 줍니다. 같은 날 같은 금액을 SPY·QQQ·SCHD·VTI(분배금 재투자)에 넣었다면의 평가금액·TWR·XIRR 비교. 간편 입력은 현금흐름 기록이 없어 "계산하지 않음"을 표시합니다. |
| **내 자산 → 목표 비중** | 종목별 목표 비중 저장(합이 100% 미만이면 나머지는 현금 목표, '현재 비중으로 채우기'·저장한 전략 불러오기), 이탈 기준(%p)을 넘으면 화면 위에 알림. **매도 포함 전체 리밸런싱**과 **매도 없이 추가 투자금만 / 보유 현금·분배금만** 쓰는 방식을 나눠 종목별 현재·목표·차이·매수/매도 금액·수량·거래 후 비중을 계산합니다. 사용자가 넣은 수수료율로 **비용 반영 전후** 비교, 정수 주 옵션, 계산에 쓴 시세 시각·지연 표시. |
| **내 자산 → 노출 분석** | ETF 상위 편입 종목(제공처 제공분)으로 **같은 종목에 대한 직접 + 간접 노출**, 보유 ETF 끼리의 **중복도**, 섹터(ETF 섹터 비중 + 주식 섹터), 유형별 비중(성장형·시장 지수형·배당형·인컴형·레버리지·금), 레버리지 ETF 비중과 배수 반영 실질 노출, M7 집중도. 상위 편입 밖은 '확인 못 한 부분'으로 남기고, 7일 넘게 갱신되지 않은 자료는 경고합니다. 레버리지 ETF(스왑·선물)와 펀드를 담은 ETF 는 편입 종목으로 펼치지 않습니다. **ETF 구성 변화**: 제공처는 지금 구성만 주므로 매일 참고 자료를 받을 때 구성(상위 편입·섹터·총보수·제공처 분류)을 직접 기록하고, 기록끼리 비교해 새로 편입·빠짐·비중 변화, 구성 변화로 달라진 종목별 간접 노출과 ETF 간 중복, 실제 지급 기록으로 본 분배 주기 변화(1년 전 vs 지금)를 보여 줍니다. 기록을 시작하기 전의 변화는 만들어 내지 않습니다. |
| **내 자산 → 변화 분석** | 전 거래일·1주·1개월·3개월·연초 이후·직접 선택 기간에 총자산이 왜 변했는지 나눕니다: 입금·출금·기초 보유, 세후 분배금, 수수료, **종목별 가격 변화**(전날 수량 × 종가 변화), **매매 시점 차이**(거래 가격과 그날 종가의 차이), 설명되지 않은 차이(0이면 빠진 항목 없음). 기간 시간가중수익률과 SPY·QQQ 비교, 가장 크게 기여·악영향을 준 종목, 종목 뉴스 바로가기. **뉴스와 가격 변화가 같은 시기라도 원인으로 단정하지 않습니다.** 간편 입력은 지금 수량을 기간 내내 보유했다고 보고 계산함을 표시합니다. |

#### 계산 가정
전체 공식·초기화·시점 규칙은 [docs/CALCULATIONS.md](docs/CALCULATIONS.md)에 정리했습니다.

- **백테스트 가격**: 분할만 반영한 실제 종가 + 배당락일의 '보유 수량 × 주당 지급액'. 수정주가와 분배금을 함께 쓰지 않아 **이중 계산이 없습니다**. 실제 데이터 검증: QQQ·TQQQ·QLD·VOO·SPY·DGRO·JEPI·JEPQ·DIVO·GLD·SCHD 의 1·5·10년 총수익률이 Yahoo 수정주가(adjclose) 기준과 0.3%p 안에서 일치했습니다.
- **재투자**: 배당락일 종가로 같은 종목 매수(세금 차감 후). 미재투자는 이자 없는 현금.
- **납입**: 월초 첫 거래일 또는 월말 마지막 거래일 종가로 목표 비중 매수. **리밸런싱**: 새 기간 첫 거래일 종가. 거래 비용은 사고판 금액에 부과.
- **수익률 지표**: CAGR·변동성·샤프·낙폭·연/월 수익률은 시간가중 수익 지수(추가 납입 효과 제외), IRR 은 금액가중. 1년 미만 기간은 연환산하지 않음. 샤프 비율의 무위험 수익률은 기간 평균 13주 국채금리(^IRX) 또는 직접 입력.
- **계산 달력**: 모든 종목에 종가가 있는 날만 사용. 가격이 없는 날을 채우지 않음. 종료일이 데이터 마지막 날 이후면 마지막 데이터 날까지 계산하고 알림.
- **미래 시나리오**: 가격 수익률 = 분배금 제외 가격 변화. 분배금은 그 달 평가금액 × 분배금 수익률 × 과거 실제 지급 월 비중. 기본 가정은 '총수익률 고정'(가격 = 총수익률 − 분배금 수익률)이라 분배금이 높다고 총수익이 높게 나오지 않습니다. 기본값 4/7/10% 는 계산용 가정이며 예측이 아닙니다. 연도별 표는 '시작 + 납입 + 가격 변화 + 세후 분배금(재투자 안 하면 현금) − 비용 = 끝'이 맞도록 계산합니다.
- **몬테카를로**: 모든 종목에 공통인 완전한 월의 실제 가격·분배금 수익률을 6개월 묶음으로 다시 뽑음(시드 고정 시 재현 가능). 공통 데이터 36개월 미만이면 실행하지 않음. '평균 수익률 맞춤'을 고르면 종목마다 월 가격 수익률을 같은 폭만큼 옮겨 기하 평균 총수익률이 정한 값이 되게 합니다(변동성·상관·묶음 순서는 그대로). 과거 그대로 쓰면 표본 기간(예: 강세장)의 수익률을 그대로 반복하므로 화면에 경고합니다.
- **분배금 감소**: 기준 = 보유 수량 × 최근 12개월 실제 주당 정기 지급액.
- **위험 예산**: 시장 하락 손실 = 평가금액 × 베타(최근 3년) × 하락률(최대 −100%). 섹터 하락 = 평가금액 × 그 섹터 비중 × 하락률 × 레버리지 배수(레버리지 ETF 는 기초 ETF 섹터 비중, 하루 만에 일어난다고 가정). 섹터 정보가 없는 부분은 추정하지 않고 '그 섹터가 전혀 없음 ~ 전부 그 섹터' 범위로 보여 줍니다. 금리 민감도 = 최근 10년 월간 총수익률을 10년물 금리(^TNX) 월간 변화(%p)에 회귀한 기울기(± 표준오차를 범위로, |상관| 0.2 미만은 '관계 약함'). 위험 기여도 = w_i × (Σw)_i ÷ wᵀΣw(최근 3년 일간 총수익률, 모든 종목에 가격이 있는 날만). 예측이 아니라 가정에 따른 계산입니다.
- **변화 분석**: 총자산 변화 = 입금 − 출금 + 기초 보유 + 세후 분배금 − 수수료 + 가격 변화 효과 + 매매 시점 효과. 평가는 일별 종가로만 하며 남는 차이를 '설명되지 않은 차이'로 그대로 보여 줍니다.
- **목표 달성 계획**: 매달 납입(월초) → 가격 변화 → 분배금(평가액 × 분배금 수익률 ÷ 12) → 세후 재투자. 가격 수익률 = 총수익률 − 분배금 수익률. 필요한 월 투자금은 이분법으로 찾습니다(최대 50년).
- **ETF 구성 기록**: 처음이거나 의미 있는 변화(편입·편출, 비중 0.5%p 이상, 섹터 1%p 이상, 총보수·분류 변경)가 있거나 마지막 기록 후 28일이 지났을 때만 새 기록을 남깁니다(그 외에는 확인 시각만 갱신).
- **하락장**: 베타 = 최근 1/3/5년 일간 총수익률의 지수 회귀. 예상 손익 = 지수가 D거래일 동안 과거 급락기(또는 최근 3년) 변동성으로 움직이며 정확히 X% 내리는 경로 800개에서 종목이 매일 '베타 × 지수 수익률'로 움직인 결과의 중앙값 → 레버리지 ETF 의 일일 배수 구조를 반영(단순 '베타 × 하락률'은 화면에서 뺐습니다). 과거 하락 구간은 실제 기록이며 상장 전 종목이 있으면 포트폴리오 결과를 계산하지 않음.
- **해외주식 양도소득세(추정)**: 1~12월 매매 손익을 합산(손실은 다음 해로 넘기지 않음) → 기본공제 250만 원 → 22%(지방소득세 포함), 다음 해 5월 신고·납부. 취득가액은 선입선출법 또는 이동평균법(증권사마다 다름), 매수·매도 금액은 거래 당시 환율(입력이 없으면 그날 원/달러 종가로 근사하고 표시)로 원화 환산, 수수료는 필요경비. 미국 분배금은 현지 15% 원천징수로 보통 국내 추가 세금이 없지만 연간 금융소득이 2,000만 원을 넘으면 종합과세 대상입니다. 실제 신고는 증권사 자료로 확인하세요.
- **목표 배당 계산기**: 필요 투자금 = 연간 목표 ÷ (가중 평균 최근 12개월 실제 분배금 수익률 × 세후 비율). '모든 달 목표 이상' = 월 목표 ÷ (분배금이 가장 적은 달의 1달러당 분배금). 최근 지급액 연환산 기준 금액은 참고로만 표시.
- **내 자산 수익률**: 종목별 총수익률 = (평가손익 + 실현손익 + 받은 분배금(세후)) ÷ 총 매수 금액(분배금 재투자 제외). 계좌 총수익률(거래 내역) = (총자산 − 순납입 원금) ÷ 순납입 원금. 간편 입력은 최초 매수일을 넣은 종목만 '그 뒤 실제 지급 × 지금 수량(세후 15%)'으로 분배금을 추정해 총수익률에 더하고, 현금 잔액과 겹칠 수 있어 총자산에는 더하지 않습니다.
- **성과 분석(TWR·XIRR)**: TWR = 매일 (오늘 평가액 − 오늘 외부 입출금) ÷ 어제 평가액을 이어 곱한 값(입출금은 그날 종가 전에 들어온 것으로 봄, 빈 계좌인 날은 건너뜀). XIRR = 입금(−)·출금(+)·기초 보유(−)와 기준일 평가액(+)의 연환산 내부수익률. 외부 입출금(입금·출금·기초 보유)은 원금 이동이고, 분배금은 계좌 안의 수익입니다. 평가에는 일별 종가만 쓰고 가격이 없는 날은 채우지 않고 뺍니다. 벤치마크는 같은 날짜·금액을 분배금 재투자 총수익 지수에 넣고 뺀 결과입니다.
- **리밸런싱**: 현재 비중 = 평가금액 ÷ (평가금액 합 + 현금). 전체 리밸런싱 거래 = 목표 비중 × (총액 − 수수료) − 현재 평가금액(수수료가 현금에서 나가도록 반복 계산). 추가 투자금·현금 방식은 매도 없이 목표보다 모자란 금액에 비례해 나누고, 다 채우고 남은 돈은 목표 비중대로 나눕니다. 수수료 = 거래 금액 × 입력한 수수료율(환전 비용·세금 제외). 정수 주는 사는 수량 내림·파는 수량 올림(보유 수량까지).
- **노출 분석**: 간접 노출 = ETF 평가금액 × 상위 편입 비중. 중복도 = 두 ETF 의 같은 종목 비중 중 작은 쪽의 합(상위 편입 기준). 섹터 = ETF 섹터 비중 × 평가금액 + 주식 섹터. 모두 상위 편입 종목 기준이라 실제 노출의 '최소한'입니다.
- **세후 분배금**: 세후 = 세전 × (1 − 고른 세율). 월 = 연 ÷ 12 평균. 재투자 가정은 분배금 수익률(최근 12개월 실제 지급 ÷ 평가액)과 입력한 가격 변화율이 매년 같다고 보고 지급마다 세후 금액을 다시 산다고 계산합니다.
- **배당 품질 비교** (`/income` → 배당 품질 비교): TTM 수익률·TTM 금액(정기 지급), 연간 변화(1년 전체가 기록된 가장 최근 연도 vs 전년), 직전 대비, 1년 가격 수익률·총수익률(배당락일 재투자), 지급 변동성 = 최근 3년 정기 지급 최대 12회의 변동 계수(표준편차 ÷ 평균; 10% 미만 작음·25% 미만 보통·그 이상 큼 — 이 사이트의 구분)와 감소 횟수, 종목별 출처·수집 시각(4일 넘게 갱신 안 되면 노란색). **분배금 구성**(배당·이자·자본이득·원금 반환 비율)은 제공처가 주지 않아 "제공처 미제공"으로 표시하고 운용사 공시로 연결합니다(추정하지 않음).
- **백테스트 재현 코드**: 데이터 코드 = 계산 기간 안 날짜·종가·분배금의 FNV-1a 해시, 설정 코드 = 계산 조건의 해시. 같은 설정과 같은 데이터 코드면 같은 결과가 나오는지 단위 테스트로 확인합니다. 데이터가 새로 수집·정정되면 코드와 결과가 달라질 수 있으며, 실제 과거 투자 결과를 그대로 재현한다는 뜻이 아닙니다.
- **알림 판단**: 변경 알림(금액·총보수·편입·새 일정)은 규칙을 만든 뒤 처음 확인한 값을 기준으로 삼아 그 뒤 달라졌을 때만 알립니다(처음에는 알리지 않음). 상태 알림(배당락 임박·가격·손익률·목표 이탈)은 조건이 새로 맞을 때 한 번 알리고, 풀렸다가 다시 맞으면 또 알립니다. 데이터가 없으면 건너뜁니다. 데이터는 수집 작업이 실행될 때 바뀌므로 그보다 빨리 알 수 없습니다.
- **원화 기준(환율 반영)**: 매수·매도·분배금·입출금은 그때 환율(입력값, 없으면 그날 원/달러 종가로 근사하고 건수 표시), 현재 평가금액은 현재 환율. 환율 효과 = 원화 총손익 − 달러 총손익 × 현재 환율. 매수 환율을 알 수 없는 종목이 있으면 원화 기준을 계산하지 않고 이유를 보여 줍니다.

#### 개인정보·로컬 저장
- 이름·이메일·전화번호·계좌번호·증권사 로그인을 요구하지 않습니다.
- 내 자산·거래·전략·결과·목표 비중·알림 규칙은 브라우저 IndexedDB(안 되면 localStorage)에 저장되며 서버·외부 분석 서비스·AI API로 보내지 않습니다. 계산도 브라우저 안에서 합니다.
- 암호화 백업: 브라우저 Web Crypto 로 PBKDF2-SHA256(60만 회) → AES-256-GCM. 비밀번호·키는 저장하지 않으므로 잊으면 복구할 수 없습니다.
- 계정이 없어도 완전한 익명은 아닙니다: 호스팅(GitHub Pages)과 뉴스 이미지 서버에는 일반적인 접속 기록(IP 등)이 남을 수 있습니다.
- 브라우저의 사이트 데이터를 지우면 저장 내용이 사라집니다 → 설정에서 백업하세요.

#### 구현하지 않은 것 (지원한다고 표시하지 않음)
- **브라우저를 닫았을 때 오는 푸시 알림**: 서버가 사용자별 알림 규칙과 푸시 구독 정보를 보관해야 해서 "개인 데이터는 브라우저에만" 원칙과 맞지 않고, GitHub Pages 에는 서버가 없어 구현하지 않았습니다. 알림은 사이트가 열려 있을 때만 확인합니다.
- **분배금 구성(배당·이자·자본이득·원금 반환) 비율**: 무료 제공처가 회차별 구성 내역을 주지 않아 표시하지 않습니다. 운용사 19a-1 공시·연말 세금 자료에서 확인하세요.
- **ETF 전체 보유 내역**: 제공처는 보통 상위 10개만 줍니다. 노출·중복 분석은 그 범위의 '최소한' 값입니다.
- **확정 세액 계산**: 분배금·양도소득세는 모두 사용자가 고른 가정에 따른 추정치입니다.
- **AI 문장으로 쓰는 투자 분석가**: 유료 AI API 를 쓰지 않는다는 원칙에 따라 만들지 않았습니다. 대신 규칙 기반 '변화 분석'(가격·매매·입출금·분배금 분해, 시장 비교)과 '투자 보고서'를 제공하며, 뉴스는 같은 기간의 자료로 연결만 하고 원인으로 단정하지 않습니다.
- **과거 ETF 구성·추종 지수·운용 방식 변경**: 무료 제공처는 과거 구성과 지수·운용 방식 변경 이력을 주지 않습니다. 구성은 이 사이트가 기록을 시작한 날부터만 비교하고, 지수·운용 방식 변경은 자동으로 확인하지 않습니다(제공처 분류가 바뀌면 표시).
- **정밀한 금리 위험(듀레이션) 분석**: 채권 듀레이션 자료가 없어 과거 수익률과 금리의 관계로만 추정합니다.
- **지표 전략의 공매도·여러 종목 동시 운용·장중 손절 체결**: 지표 전략 검증은 한 종목 롱 온리(보유 또는 현금)이며 손절·익절도 종가로 판단해 다음 봉에 체결합니다. 장중 고가·저가로 체결됐다고 가정하지 않습니다.
- **생존 편향 없는 종목 집합**: 지원 종목은 지금 상장된 종목이라 상장 폐지된 종목은 백테스트에 들어 있지 않습니다(화면에 표시).
- **시장 충격 비용 모형**: 거래 비용은 사용자가 넣은 수수료율·슬리피지(bp)로만 계산합니다. 주문 크기에 따른 가격 충격은 넣지 않습니다.
- **GitHub Pages 의 보안 헤더(CSP 등)**: 정적 호스팅은 응답 헤더를 바꿀 수 없어 서버 모드(`npm start`)에서만 보냅니다.
- **실제 롱·숏 포지션 비율**: 미국 투자자 전체의 종목별 롱·숏 비율을 공개하는 신뢰할 수 있는 무료 자료가 없습니다(IG·eToro 는 자사 고객 한정, Nasdaq RTAT 전체판·Ortex 는 유료, NAAIM 은 2026-08부터 구독제). 다른 지표를 합쳐 만들지도 않습니다.
- **종합 심리 점수**: 서로 다른 자료를 임의 가중치로 합친 점수는 검증할 수 없어 만들지 않았습니다.
- **AAII 전체 과거 자료**: 공개 페이지의 최근 결과만 매주 모읍니다(전체 과거 엑셀은 재배포하지 않음). 그래서 추이는 수집을 시작한 뒤부터 쌓입니다.

### 배당·분배금
- 기업 주식은 "배당금", ETF는 "분배금"으로 구분해 표시합니다.
- 보여 주는 항목:
  - 최근 지급액, 배당락일, 지급일
  - 직전 대비, 1년 전 같은 회차 대비 변동
  - 최근 12개월(TTM) 합계와 TTM 수익률
  - 최근 지급액 연환산 수익률(참고값)
  - 지급 주기: 실제 지급 기록으로 판정하고, 제공처가 밝힌 값도 함께 표시
  - 발표된 다음 분배금
  - 지급 변동성(최근 정기 지급의 변동 계수·감소 횟수)과 분배금 구성 자료 여부(제공처 미제공이면 그렇게 표시)
  - 연도별 합계, 지급 기록 그래프, 과거 지급 내역 표(배당락일, 지급일, 주당 지급액, 지급 유형, 출처)
- 계산 방식은 화면에 그대로 적어 둡니다. 연환산은 지급 주기가 규칙적일 때만 계산하고, "확정 연간 지급액이 아님"을 함께 표시합니다.
- 특별배당과 자본이득 분배는 정기 지급과 따로 집계합니다. 주식분할 이전 지급액은 분할 비율로 조정합니다.
- 가격 수익률, 총수익률(재투자 가정), 총수익률(현금 수령)을 1·3·5년 기준으로 나눠 보여 줍니다.
- 커버드콜·옵션 인컴 ETF에는 옵션 프리미엄, 자본환급(ROC) 가능성, "높은 분배율이 높은 총수익을 뜻하지 않음" 안내를 붙입니다.
- 기록이 없으면 "데이터 미제공"으로 표시하고 예시 값을 채우지 않습니다.

### 종목별 일일 투자 브리핑 (핵심 기능)
각 종목 브리핑은 그 종목에 저장된 데이터만으로 만듭니다. 항목은 다음과 같습니다.
1. 핵심 요약
2. 주가 움직임: 등락, 갭, 일중 위치, 거래량 대비 20일 평균, 최근 5거래일, 5분봉 장중 흐름, 기준 지수·기초자산 비교
3. 관련 뉴스: 수집 구간 안의 기사만 넣고 중복은 통합합니다. 기사마다 제목, 요약, 게시 시각, 출처, 원문 링크, 관련 이유를 붙입니다.
4. 기술적 분석: 계산 결과와 해석을 나눠 보여 주고, 지지·저항은 "분석상 참고 수준"으로 표시합니다.
5. 앞으로 확인할 사항: 실적 발표, 편입 종목 실적, 배당락·지급일, 경제지표, 휴장일
6. 주요 위험 요인: 상품 유형별 일반 설명과 데이터에 근거한 현재 관찰을 나눠 씁니다.
7. 데이터와 분석의 기준: 분석 기준일, 주가 기준 시각, 뉴스 수집 시각, 제공처, 한계, 근거 자료 목록

종목 유형별 차별화:

| 유형 | 브리핑에서 다루는 내용 |
|---|---|
| TQQQ·QLD 등 레버리지 | 기준 지수 등락률×배수와 실제 등락률의 차이. 20거래일 복리 효과 차이. 기준 지수 실현 변동성 |
| JEPI·JEPQ·DIVO 등 인컴 | 기준 지수 대비 상승·하락 참여 방식. 분배금 변동. 1년 가격 수익률과 분배금 포함 수익률 |
| GLD·IAU·GLDM | 금 선물 대비 움직임, 10년물 금리, 달러 인덱스. 기업 실적 대신 금 가격 중심 |
| 지수·섹터 ETF | 상위 편입 종목 기여도(비중×등락률, 근사). 상위 10개 집중도. 편입 종목 실적 일정 |
| M7 | 기준 지수 대비 성과. 실적 발표 일정. 밸류에이션 지표(사실만 표시) |

문장마다 성격 배지를 붙입니다.
- `사실`: 수집 데이터로 확인된 사실
- `계산`: 수집 데이터로 계산한 값
- `분석 해석`: 사이트의 규칙 기반 해석
- `보도된 시장 해석`: 기사에 실린 시장 참여자의 해석
- `AI 분석`: AI가 근거 자료만으로 작성한 문장
- `안내`: 데이터 한계 안내

문장마다 근거 ID(예: `[P1]`, `[N2]`)가 붙고, 근거 자료 목록으로 이어집니다.

### 데이터 신뢰 원칙 (구현 방식)
- 화면의 모든 수치에는 출처와 갱신 시각이 붙습니다.
- 최신 조회에 실패하면 저장된 과거 데이터에 **"최신 조회 실패 — 저장된 과거 데이터 표시 중"** 경고를 붙입니다. 과거 데이터를 현재 데이터처럼 보여 주지 않습니다.
- 데이터가 없으면 "데이터 미제공"으로 표시하고 예시 값이나 추정 값을 채우지 않습니다.
- 뉴스는 수집 구간 밖의 기사를 오늘 뉴스로 표시하지 않습니다. 게시 시각은 항상 함께 표시합니다.

## 4. 자동 업데이트(스케줄러)

워커(`npm run worker`)가 미국 동부 시간과 NYSE 휴장일·조기 폐장을 반영해 다음 작업을 실행합니다.

| 작업 | 기본 일정 (ET) | 내용 |
|---|---|---|
| `refresh_quotes` | 거래일 04:00~20:00, 15분마다 (휴장일은 10:00 1회) | 지원 종목, 시장 지표, ETF 상위 편입 종목 시세 |
| `collect_news` | 매일 06:00~22:00, 2시간마다 | 종목·시장 뉴스 수집, 관련 이유 분류 |
| `collect_reference` | 매일 07:00 | 기업·ETF 지표(20시간 이내 수집분은 생략), SEC 재무(주 1회), 실적·경제 일정, 거시 지표 |
| `collect_eod` | 정규장 마감 15분 후 | 일봉, 5분봉, 배당 상세(인컴·배당 ETF는 매일, 나머지는 주 1회) |
| `briefing_intraday` | 거래일 12:30 | 장중 브리핑. "확정 전 데이터"로 표시 |
| `briefing_close` | 정규장 마감 25분 후 (조기 폐장일은 13:00 기준) | 일봉이 마감 이후 갱신됐는지 확인한 뒤 장 마감 후 브리핑 생성 |
| `briefing_non_trading` | 주말·공휴일 10:00 | 마지막 거래일 기준 정보와 새 뉴스만 정리합니다. 당일 주가 분석은 만들지 않습니다. |
| `collect_positioning` | 정규장 마감 15분 후 | 공매도 잔고(FINRA, 최근 13개월)·일일 공매도 거래량(빠진 날만)·종목 옵션 합계(마감 후 10시간 이내, 기준일 확인)·Cboe 시장 옵션(빠진 날만, 처음 약 1년)·AAII 설문·기관 13F(새 제출만). 출처마다 따로 처리해 일부 실패는 부분 성공 |
| `cleanup` | 매일 03:30 | 만료 캐시, 오래된 분봉·뉴스·로그 정리 |

- 생성 과정: 실제 주가·거래량 수집 → 뉴스·기업 정보 수집 → 일정·분배금 확인 → 종목별 정리 → 브리핑 생성 → 브리핑과 근거 자료 저장(`briefings` 테이블) → 웹사이트 표시.
- 화면을 새로고침해도 새 분석 글을 만들지 않습니다. 저장된 브리핑을 보여 줍니다.
- 작업 결과는 `job_runs`에 슬롯 단위로 기록됩니다. 실패하면 15분 간격으로 최대 4회 재시도합니다.
- 제공처 연결이 3회 연속 실패하면 2분 동안 호출을 멈춥니다(서킷 브레이커). 장애 중에 작업이 재시도 대기로 오래 멈추는 것을 막기 위해서입니다.
- 워커가 늦게 시작해도 마지막 완료 거래일의 장 마감 데이터와 브리핑을 따라잡습니다(4일 이내).
- 일정은 설정 페이지에서 바꿀 수 있습니다(관리자 토큰 필요). 수동 실행은 `npm run job -- <작업명> [--force] [--date YYYY-MM-DD] [--symbols QQQ,JEPI]`로 합니다.

## 5. 설치·실행

요구 사항은 **Node.js 22.13 이상**입니다. 내장 `node:sqlite`를 쓰므로 네이티브 모듈 빌드가 필요 없습니다.

```bash
npm ci
cp .env.example .env        # 필요한 키 입력 (아래 6번 참고)
npm run build

# 웹 서버 + 스케줄러를 함께 실행
npm run start:all           # http://localhost:3000

# 또는 따로 실행
npm start                   # 웹 서버
npm run worker              # 스케줄러 (자동 업데이트·브리핑 생성)

# 처음 데이터를 바로 채우려면
npm run job -- all          # 시세 → 참조 데이터 → 마감 데이터 → 뉴스 → 장 마감 후 브리핑
```

개발 모드는 `npm run dev`입니다. 테스트는 다음과 같습니다.

```bash
npm run typecheck
npm run lint                # ESLint (Next.js 권장 규칙 + TypeScript)
npm test                    # 단위 테스트 (지표 기준값·속성, 회계 기준값·무작위 거래, 성과·위험 지표 기준값, 지표 전략·미래 정보 검사, 백테스트·수익률·양도세·미래·스트레스·DB 동시 접근, 성능 상한)
npm run build && npm run test:e2e   # 합성 데이터 모의 서버로 전체 흐름 + 브라우저 검증
npm run bench               # 계산 성능 측정 (합성 데이터, 외부 호출 없음)
npm run verify:static       # build:static 뒤 결과물 점검 (필수 파일·JSON·시세 값·API 키 노출)
```

**자동 검사 (GitHub Actions)**
- `CI` (모든 푸시·PR): 타입 검사 → 린트 → 단위 테스트 → 서버 빌드 → 정적 빌드. 별도 작업으로 서버 모드 e2e → 합성 데이터로 예약 작업과 같은 수집(`tests/e2e/make-static-db.ts`) → 정적 빌드 → `verify:static` → 정적 e2e. 실패하면 스크린샷·로그를 7일 보관합니다.
- `정적 사이트 갱신` (배포): 데이터 수집·DB 저장 뒤 **타입 검사·단위 테스트가 실패하면 빌드·배포를 하지 않고**, 빌드 뒤 `verify:static`(실제 API 키 값과 대조)이 실패해도 배포하지 않습니다. 수집한 데이터는 그대로 저장되어 다음 실행에 이어집니다.

> e2e 는 내 자산 입력·새로고침 후 유지·간편→거래 전환·매수/매도/입출금/분배금/재투자 계산·수익률(달러/원화 기준)·사용자 지정 기간 백테스트·상장일 검증·비중 확인·미래 기간 입력·몬테카를로·분배금/하락장 스트레스 테스트·전략 저장/복제/내보내기·일반/암호화 백업과 복원·초기화·모바일 화면까지 확인합니다 (`tests/e2e/features.ts`).
>
> `test:e2e`는 `tests/e2e/mock-upstream.ts`의 **합성(가짜) 데이터 서버**를 사용합니다. 테스트에만 쓰고, 애플리케이션 코드는 이 서버를 참조하지 않습니다.

## 7. 배포

### 7-1. GitHub Pages로 무료 운영 (PC를 켜 두지 않아도 됨)

GitHub Actions가 정해진 시각에 데이터를 수집하고 브리핑을 만든 뒤, 정적 사이트로 빌드해 GitHub Pages에 올립니다.
공개 저장소에서는 Actions와 Pages가 무료입니다(2026년 기준, 요금 정책은 GitHub 공지를 확인하세요).

**처음 한 번 설정**
1. 저장소를 공개로 바꿉니다: Settings → General → Danger Zone → Change visibility → Public
2. 이 워크플로가 있는 브랜치를 기본 브랜치(main)에 병합합니다. 예약 실행은 기본 브랜치에서만 동작합니다.
3. Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 바꿉니다.
4. Settings → Secrets and variables → Actions → New repository secret에서 키를 넣습니다.
   - `SEC_USER_AGENT` (예: `MyStockSite 본인이메일@example.com`), `FINNHUB_API_KEY`, `FRED_API_KEY`
   - 선택: `POLYGON_API_KEY`, `ALPHAVANTAGE_API_KEY`, `ANTHROPIC_API_KEY`(유료)
5. Actions 탭 → **정적 사이트 갱신** → Run workflow → mode에서 `all`을 골라 실행합니다(처음 전체 수집, 10~20분).
6. 끝나면 `https://<GitHub 사용자명>.github.io/<저장소 이름>/` 에서 열립니다.

**동작 방식**
- 예약 실행 시각(한국 시간): 평일 22:45·00:45·02:45·04:45(미국 장중), 07:20(장 마감 후 브리핑), 주말 00:30. 시각은 `.github/workflows/pages.yml`의 `cron`(UTC)에서 바꿉니다.
- 실행할 때마다 `npm run job -- due`로 그 시각에 해야 할 작업(시세·뉴스·장 마감 데이터·브리핑)을 처리합니다.
- 수집한 DB는 압축해서 `data` 브랜치에 저장하고 다음 실행 때 불러옵니다. 이 브랜치는 매번 덮어씁니다.
- 화면 위에 "정적 스냅샷" 안내와 페이지 생성 시각이 표시됩니다. 실시간 시세가 아니며 시세에는 "수집 시점 스냅샷"이라고 표시됩니다.
- API 키는 GitHub Secrets에만 있고 사이트 파일에는 들어가지 않습니다.

**제약**
- GitHub 사정으로 예약 실행이 수십 분 늦어지거나 건너뛰어질 수 있습니다.
- 공개 저장소에 60일 동안 활동이 없으면 GitHub이 예약 실행을 멈춥니다. 워크플로가 매번 다시 활성화를 시도하지만 효과는 보장되지 않습니다. 멈추면 Actions 탭에서 다시 켜면 됩니다.
- Yahoo·Nasdaq 같은 비공식 제공처가 GitHub 서버의 접속을 막을 수 있습니다. 사이트의 데이터 상태 화면이나 Actions 실행 기록에서 확인하세요.
- 1분봉, 설정 화면의 일정 변경·수동 실행, 브리핑 기록(최근 30건 초과)은 정적 사이트에서 제공하지 않습니다.
- 사이트 주소를 아는 사람은 누구나 볼 수 있습니다.

로컬에서 정적 사이트를 미리 확인하려면 `BASE_PATH=/stock_chart npm run build:static` 후 `npm run test:e2e:static`을 실행합니다. 합성 데이터로 확인하려면 먼저 `npx tsx tests/e2e/make-static-db.ts e2e-out/static.db` 로 DB 를 만들고 `DATABASE_PATH=e2e-out/static.db` 를 붙여 빌드합니다.

### 7-2. 서버에 배포

이 사이트는 **SQLite 파일과 상시 실행 워커**를 쓰므로, 디스크가 유지되는 단일 서버(VM·VPS·컨테이너)에 배포하는 것을 권장합니다.

**Docker**
```bash
cp .env.example .env   # 키 입력
docker compose up -d --build     # http://서버:3000, 데이터는 ./data 에 저장
```

**일반 서버 (systemd·pm2 등)**
```bash
npm ci && npm run build
DATABASE_PATH=/var/lib/usi/app.db npm run start:all
```

- 서버에서 데이터 제공처 호스트로 나가는 HTTPS가 허용되어야 합니다: `query1/query2.finance.yahoo.com`, `fc.yahoo.com`, `api.nasdaq.com`, `data.sec.gov`, `finnhub.io`, `api.polygon.io`, `api.stlouisfed.org`, `www.alphavantage.co`, `news.google.com`, `api.anthropic.com`.
- Vercel 같은 서버리스 환경은 파일 DB와 상시 워커를 유지할 수 없어 그대로는 맞지 않습니다. 쓰려면 외부 DB(예: Postgres)와 외부 cron으로 바꿔야 합니다.
- 클라우드 IP에서는 Yahoo·Nasdaq 비공식 엔드포인트가 막힐 수 있습니다. 데이터 상태 페이지에서 제공처별 실패를 확인하세요.
